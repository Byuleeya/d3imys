# 용산 IMAX 〈듄: 파트 3〉 새 예매 날짜 알림 v1

이번 판은 과거 CGV 용산 4DX RELAY v4-cachebust의 **조회 → 판별 → 텔레그램 알림** 구조를 IMAX 새 예매일 감시에 맞게 재구성했습니다. 로그인, 좌석 배치도, 자동 홀딩, 결제는 전혀 없습니다. 브라우저도 설치하지 않아 Docker 이미지가 작습니다.

## 현재 기준 / 감시 범위

2026-11-25 보도 기준 CGV 용산 IMAX의 〈듄: 파트 3〉가 2026-12-16~12-20까지 오픈되어 있습니다. 이 5일은 감시에서 **원천 제외**하고, `START_DATE=20261221`부터 차례로 확인합니다. 기본 종료 검색 날짜 `END_DATE=20270110`은 필요하면 수정할 수 있습니다.

- 극장: CGV 용산아이파크몰 `0013`
- 영화번호: CGV `30001790` (듄-파트 3)
- 포맷: IMAX만 (일반관·4DX·다른 듄 작품 제외)
- 기본 조회: 5~7초 랜덤, 가장 가까운 미오픈 날짜에 집중. 5회 중 1회는 그 뒤의 날짜들을 순환 확인
- 알림: 해당 날짜의 IMAX 회차가 확인되면 시간·잔여 좌석수(있는 경우)와 CGV 예매 링크 전송
- 제외: 2026-12-16~20 이미 열린 회차, 기존 회차의 단순 잔여석 증감
- 2명 연석 자동 선택과 관련된 기능 없음

## 주의: 이번 버전의 조회는 실서버 검증 전

과거 정상 이용했던 공개 relay `https://mcp.aka.page/api/cgv/timetable`을 1차로 사용합니다. 하지만 2026-11-25 웹 검색 환경에서 해당 relay의 정상 응답을 확인하지 못했습니다(503 또는 접근 불가). 보조로 현재 CGV 공개 시간표 API `https://cgv.co.kr/api/v1/booking/searchMovScnInfo`를 사용하며, 이 경로는 Railway 같은 데이터센터에서 403을 반환할 수 있습니다.

**두 경로가 모두 실패하면 실제 예매 오픈을 감지할 수 없으므로 오류 로그와 텔레그램 경고가 발생합니다.** 성공을 보장하지 않습니다. 계정 로그인이나 보안 제한 우회 로직은 없습니다.

시작 시 이미 예매 열린 것으로 확인된 12/20에 듄3 IMAX가 있는지 1회 조회하여 **데이터 경로 건전성 검사**를 합니다. 이 검증에 실패하면 미오픈으로 오인해 계속 성공 로그를 남기지 않고 경고·재검증합니다. 12/20 이후에 처음 시작하는 경우에는 과거 상영 정보가 더 이상 검색되지 않을 수 있어 이 검증을 생략합니다.

## Railway 설치

1. 이 ZIP 압축을 풀고 내부의 모든 파일을 GitHub 새 private repo 최상위 폴더에 올립니다. 과거 좌석 홀딩 봇과 **같은 서비스로 섞지 마세요**.
2. Railway에서 **New Project → Deploy from GitHub Repo**로 연결합니다.
3. Railway Variables의 다음 2개만 필수 입력합니다.
   - `TELEGRAM_BOT_TOKEN` = 기존 텔레그램 봇 토큰
   - `TELEGRAM_CHAT_ID` = 기존 채팅 ID
4. 배포 후 **Deploy Logs**를 확인합니다. `기준일 20261220 검증 성공` → `감시 시작` 순서가 정상입니다.
5. 상태 저장을 배포 후에도 유지하고 싶다면 Railway Volume을 만들고 mount path `/data`로 설정하세요. Volume 없이도 실행되지만 재배포 시 알림 중복이 생길 수 있습니다.

`railway.json`은 Dockerfile을 사용하고, 포트를 열 필요 없습니다. Public Networking/Chromium/Playwright 없음.

## 변경 가능한 환경변수

`.env.example` 참고. 특히 `START_DATE`, `END_DATE`는 YYYYMMDD. `POLL_MIN_SECONDS=5`, `POLL_MAX_SECONDS=7`이 기본입니다.

`CACHE_BUST=true`는 요청 URL에 고유 query 인자를 붙여 CDN 캐시 재사용을 피하려는 시도이며, 실제 서버 내부 캐시에는 영향이 없을 수 있습니다.

## 알림이 나오면

메시지의 CGV 링크를 눌러 직접 좌석을 선택하세요. 이 프로그램은 상영 회차의 존재와 잔여 좌석 숫자만 파악하며 **개별 좌석 위치나 중앙 명당 여부는 알 수 없습니다.**

## 오류 대응

`모든 시간표 조회 경로 실패`, `HTTP 403`, `HTTP 429`, `HTTP 503`, `기준일 검증 실패`가 보이면 감시 중이 아니므로 로그를 확인하세요. 일반 오류는 점증 대기, 명시적 제한은 더 긴 대기 후 재시도합니다. CAPTCHA나 IP 우회는 하지 않습니다.
